# Split filter state strategy: React state for tasks, URL params for projects

Task filters on All My Tasks and Daily Focus use React client state; project filters on the Project Overview use URL search params. The split is intentional: task lists are personal (one user's tasks, typically 20–50 items) and filtering should feel instant — client-side in-memory filtering is appropriate and there is no shareability requirement for mid-session task filtering. Project lists benefit from URL params because the Client, Status, and Staleness filters represent views a team lead might want to share or bookmark, and the pages are server components that already use URL params for other controls (time window toggle). Unifying on one approach would mean either sacrificing the snappiness of task filtering or losing shareability on project filters.
